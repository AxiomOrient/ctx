# ctx 시작하기

**마지막 업데이트: 2025-08-30**

## 1. 개요

이 문서는 `ctx`를 처음 사용하는 개발자를 위해 설치, 설정, 그리고 핵심 기능 실행 방법을 안내합니다.

## 2. 설치

Rust 개발 환경(`rustup`, `cargo`)이 설정되어 있다고 가정합니다.

```bash
# 1. 저장소를 클론합니다.
git clone https://github.com/axient/ctx.git
cd ctx

# 2. 소스 코드를 빌드합니다.
# Tauri UI를 포함하여 전체 기능을 빌드하려면 --features 플래그가 필요할 수 있습니다.
cargo build --release --features ui_tauri

# 3. (선택) 빌드된 바이너리를 경로에 추가합니다.
# target/release/ctx
```

## 3. 설정

`ctx`는 `config.toml` 파일을 통해 동작을 설정합니다. 프로젝트 루트에 있는 `config.example.toml`을 복사하여 `config.toml`을 생성하고 필요에 맞게 수정합니다.

```toml
# config.toml 예시

# 컨텍스트 문서가 위치한 기본 경로
# base_dir = "/path/to/your/documents"

# 사용할 AI 제공자 설정
[ai]
provider = "openai" # 또는 "gemini" 등

[ai.providers.openai]
api_key = "sk-..."
model = "gpt-4-turbo"
```

## 4. 핵심 기능 실행: 프롬프트 생성

`ctx`의 핵심 기능은 CLI를 통해 프롬프트를 생성하는 것입니다. (Tauri UI를 통해서도 동일한 기능을 사용할 수 있습니다.)

```bash
# 'compose' 하위 명령어를 사용하여 프롬프트를 생성합니다.
# --query: AI에게 던질 질문
# --context-files: 컨텍스트로 사용할 파일 경로
# --system-prompt: 시스템 프롬프트로 사용할 파일 경로

./target/release/ctx compose \
    --query "이 코드의 문제점을 알려주고 개선해줘." \
    --context-files "./src/main.rs" "./src/lib.rs" \
    --system-prompt "./docs/ARCHITECTURE.md"
```

위 명령을 실행하면, `ctx`는 `ARCHITECTURE.md`를 시스템 프롬프트로, `main.rs`와 `lib.rs`를 컨텍스트로 사용하여 "이 코드의 문제점을 알려주고 개선해줘"라는 질문에 대한 최적의 프롬프트를 생성하고, 설정된 AI 모델로 전송한 뒤 결과를 반환합니다.

## 5. 핵심 개념

`ctx`를 효과적으로 사용하기 위해 알아야 할 핵심 개념입니다.

- **결정론적 파이프라인**: `ctx`의 모든 프롬프트 생성은 7단계의 예측 가능한 파이프라인을 거칩니다. 이는 일관된 결과를 보장합니다.
- **지식 베이스 (`knowledge/`)**: `ontology.yaml`과 `rules.yaml` 파일은 AI가 컨텍스트를 더 깊이 이해하고 분류하는 데 사용되는 두뇌 역할을 합니다.
- **상수 기반 결정론성 (`domain/constants/`)**: 파이프라인의 모든 가중치와 임계값은 코드로 중앙 관리되어, 동일 입력에 대한 동일 출력을 보장하는 핵심 요소입니다.
- **드라이버 (`drivers/`)**: AI 모델, 스토리지 등 외부 시스템과의 연동을 담당하는 추상화된 인터페이스입니다. 이를 통해 `ctx`는 특정 기술에 종속되지 않습니다.
