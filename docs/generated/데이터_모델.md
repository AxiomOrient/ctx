# ctx 데이터 및 지식 관리

**마지막 업데이트: 2025-08-30**

## 1. 개요

`ctx`는 결정론적 프롬프트 생성을 위해 여러 종류의 데이터와 지식을 관리합니다. 데이터는 그 성격과 사용 방식에 따라 파일 시스템, 외부 지식 베이스, 그리고 인메모리 캐시 등 각기 다른 방식으로 처리됩니다.

## 2. 파일 기반 컨텍스트 문서

- **대상**: 프롬프트 생성의 원재료가 되는 모든 소스 문서 (주로 Markdown 파일).
- **처리 방식**:
    1.  사용자가 요청 시 파일 경로를 제공하면, `drivers/storage/local.rs`의 `LocalFsStorage`가 파일 시스템에서 해당 문서를 읽습니다.
    2.  읽어온 파일 내용은 `src/doc` 파서에 의해 `ContextDocument`라는 표준화된 도메인 객체로 변환됩니다.
    3.  이 과정에서 문서의 Frontmatter와 본문이 파싱되고, `doc/validate` 모듈을 통해 데이터의 정합성(스키마, 구조 등)이 검증됩니다.
- **선택 이유**:
    - **유연성**: 개발자는 기존에 사용하던 어떤 형태의 문서나 코드 파일도 컨텍스트의 소스로 활용할 수 있습니다.
    - **단순성**: 시스템은 특정 데이터베이스나 복잡한 스키마에 종속되지 않고, 단순한 파일 I/O를 통해 데이터를 처리합니다.

## 3. 외부 지식 베이스 (YAML)

- **대상**: 시스템의 분류 및 추론 규칙을 정의하는 `ontology.yaml`과 `rules.yaml` 파일.
- **저장 위치**: `src/knowledge/`
- **처리 방식**:
    1.  `knowledge/loader.rs`가 YAML 파일들을 읽어들입니다.
    2.  파싱된 내용은 `ClassifierEngine`이 문서를 분류하고 의미를 이해하는 데 사용하는 핵심 지식으로 활용됩니다.
- **선택 이유**:
    - **지식과 코드의 분리**: 코드 변경이나 재배포 없이 YAML 파일만 수정하여 시스템의 추론 능력을 업데이트할 수 있습니다. 이는 유지보수성과 확장성을 크게 향상시킵니다.
    - **가독성**: YAML 형식은 사람이 쉽게 읽고 편집할 수 있어 지식 관리가 용이합니다.

## 4. 스토리지 및 인메모리 캐시

- **추상화**: `drivers/storage/mod.rs`는 `Storage` 트레이트를 정의하여 데이터 저장 방식에 대한 추상화(Port)를 제공합니다. 이를 통해 로컬 파일 시스템 외에 다른 방식(e.g., 원격 DB)의 저장소를 쉽게 구현하고 교체할 수 있습니다.
- **기본 구현**: `LocalFsStorage`는 로컬 파일 시스템에 접근하는 기본 어댑터(Adapter)입니다. 경로 순회 공격(Path Traversal)을 방지하는 보안 로직을 포함하고 있습니다.
- **성능 최적화**: `drivers/storage/cache/` 모듈은 자주 접근하는 데이터나 계산 비용이 높은 처리 결과를 저장하기 위한 고성용 인메모리 캐싱 시스템을 제공합니다. LRU(Least Recently Used) / TTL(Time To Live) 정책을 기반으로 동작하여 시스템의 전반적인 성능을 향상시킵니다.
