# ctx 시스템 아키텍처

**마지막 업데이트: 2025-08-30**

## 1. 개요

`ctx`는 AI 프롬프트 엔지니어링의 **결정론성(Determinism)**과 **재현성(Reproducibility)**을 보장하기 위해 설계된 컨텍스트 관리 및 생성 시스템입니다. 이 문서는 `ctx`의 아키텍처 원칙, 각 모듈의 상세 분석, 그리고 시스템의 전체적인 데이터 흐름을 기술합니다.

## 2. 핵심 설계 원칙

- **계층형 아키텍처 (Layered Architecture)**: 외부 세계와의 상호작용(`drivers`), 애플리케이션의 진입점 및 UI(`app`), 핵심 비즈니스 로직(`services`, `pipeline`), 그리고 순수 데이터 모델(`domain`)을 명확히 분리합니다.
- **단방향 의존성 (Unidirectional Dependency)**: 의존성은 항상 외부 계층에서 내부 계층으로 흐릅니다 (`app` → `services` → `pipeline` → `domain`). 이 규칙은 Rust의 모듈 시스템을 통해 컴파일 타임에 강제됩니다.
- **관심사 분리 (Separation of Concerns)**: 외부 기술(DB, Web, AI API)은 `drivers`에, 핵심 로직은 `pipeline`과 `domain`에 캡슐화하여 기술 변화에 유연하게 대응합니다.

## 4. 계층별 상세 설명

| 계층 | 모듈 경로 | 책임 | 핵심 분석 및 설계 패턴 |
| :--- | :--- | :--- | :--- |
| **진입점** | `src/main.rs` | **최종 진입점**: `tokio::main`을 사용하여 비동기 `app::run_app`을 실행하고, 사용자 친화적인 에러 메시지를 처리합니다. | 단일 책임 원칙 |
| **애플리케이션** | `src/app` | **애플리케이션 진입 및 UI 백엔드**: `clap`을 이용해 CLI 모드를 분기하고, Tauri UI의 백엔드 로직을 처리합니다. | Mode Switcher, Facade Pattern |
| **프론트엔드** | `apps/ui` | **프론트엔드 UI**: Svelte 5 기반의 모던 SPA. 백엔드에서 살균된 HTML만 렌더링하여 보안을 강화합니다. | Component-Based, SSOT |
| **서비스** | `src/services` | **유스케이스 파사드**: `Pipeline`의 복잡한 로직을 `compose_prompt` 등 단순한 유스케이스로 캡슐화하여 제공합니다. | Facade Pattern |
| **드라이버** | `src/drivers` | **외부 시스템 연동**: `Storage` 트레이트(Port)와 구현체(Adapter)를 통해 외부 기술을 추상화합니다. | Ports and Adapters |
| **파이프라인** | `src/pipeline` | **핵심 처리 파이프라인**: 7단계(정규화, 분류, 점수화, 선택 등)의 명확한 데이터 처리 흐름을 정의합니다. | Pipeline Pattern, Strategy Pattern |
| **도메인** | `src/domain` | **핵심 데이터 및 규칙**: `ContextDocument`, `Rule` 등 핵심 비즈니스 개념과 **결정론의 원천**인 `constants`를 정의합니다. | Rich Domain Model, Newtype Pattern |
| **지식** | `src/knowledge` | **외부 지식 베이스**: `ontology.yaml`, `rules.yaml`을 로드하여 코드 변경 없이 시스템 로직을 수정할 수 있는 유연성을 제공합니다. | 지식과 코드의 분리 |
| **문서 처리** | `src/doc` | **문서 파싱 및 검증**: 마크다운을 `ContextDocument`로 변환하고 데이터 정합성을 보장합니다. | Parser & Validator |
| **유틸리티** | `src/util` | **공용 유틸리티**: 결정론적 해시, 파일 시스템, Git 연동 등 저수준 유틸리티를 제공합니다. | 공용 라이브러리 |
