# ctx 핵심 설계 원칙

**마지막 업데이트: 2025-08-30**

`ctx`는 복잡한 AI 통합 시스템을 지속 가능하고 확장 가능하게 만들기 위해 다음과 같은 핵심 설계 원칙을 따릅니다.

### 1. 결정론성 및 재현성 (Determinism & Reproducibility)

- **최우선 목표**: `ctx`의 가장 핵심적인 원칙입니다. 동일한 버전의 코드, 입력 문서, 규칙에 대해 항상 동일한 프롬프트 결과를 생성하는 것을 보장합니다.
- **구현 방법**: `domain/constants` 모듈에서 모든 가중치와 임계값을 상수로 중앙 관리하고, MMR과 같은 결정론적 알고리즘을 사용하여 결과의 예측 가능성을 확보합니다.
- **기대 효과**: 결과가 일관되므로 테스트 자동화가 용이해지고, 문제 발생 시 디버깅이 수월해집니다.

### 2. 계층형 아키텍처 (Layered Architecture)

- **구조**: 외부 세계와의 상호작용(`drivers`), 애플리케이션 진입점(`app`), 핵심 비즈니스 로직(`services`, `pipeline`), 순수 데이터 모델(`domain`)을 명확히 분리합니다.
- **장점**: 각 계층은 자신만의 명확한 책임을 가지므로 코드의 복잡성이 관리되고, 유지보수 및 기능 확장이 용이해집니다.

### 3. 단방향 의존성 (Unidirectional Dependency)

- **규칙**: 의존성 흐름은 항상 외부 계층에서 내부 계층으로만 향합니다 (`app` → `services` → `pipeline` → `domain`). 내부 계층은 외부 계층의 존재를 알지 못합니다.
- **강제성**: 이 규칙은 Rust의 모듈 시스템을 통해 컴파일 타임에 강제되므로, 의도치 않은 의존성 순환을 원천적으로 방지하고 시스템의 안정성을 높입니다.

### 4. 관심사 분리 (Separation of Concerns)

- **외부 기술 분리**: 데이터베이스, 웹 프레임워크, AI API와 같은 외부 기술은 `drivers` 계층에 캡슐화됩니다. 이를 통해 핵심 비즈니스 로직(`pipeline`, `domain`)에 영향을 주지 않고 특정 기술을 교체하거나 업그레이드할 수 있습니다.
- **지식과 코드 분리**: `knowledge` 디렉토리에 시스템의 추론 규칙을 YAML 파일로 분리하여, 코드 배포 없이도 AI의 행동을 수정할 수 있는 유연성을 확보합니다.
